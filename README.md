# Telegram Bot Manager

پنل مدیریتی داخل تلگرام برای مدیریت متمرکز چندین ربات تلگرام، ساخته شده با
**Python 3.12+** و **Aiogram 3**.

با این پروژه یک "ربات مدیر" اجرا می‌کنید که از طریق منوی داخل تلگرام امکان
افزودن، مشاهده، فعال/غیرفعال کردن، تغییر تنظیمات و حذف ربات‌های دیگر را در
اختیارتان می‌گذارد. هر ربات ثبت‌شده به‌صورت یک نمونهٔ (instance) کاملاً مستقل
با توکن خودش به API تلگرام وصل می‌شود.

## ✨ امکانات

- ➕ افزودن ربات جدید با اعتبارسنجی زندهٔ توکن از طریق متد `getMe`
- 📋 لیست تمام ربات‌های ثبت‌شده به همراه وضعیت فعال/غیرفعال و در حال اجرا
- ⚙️ تنظیمات هر ربات: فعال‌سازی، غیرفعال‌سازی و تغییر ایموجی ری‌اکشن
- ❌ حذف ربات با مرحلهٔ تأیید
- 🗄️ ذخیره‌سازی کامل در SQLite (بدون وابستگی به سرویس خارجی)
- 📝 سیستم لاگ حرفه‌ای (فایل لاگ عمومی + فایل لاگ خطاها + کنسول)
- 🔒 دسترسی محدود به ادمین‌های تعریف‌شده، بدون نمایش کامل توکن‌ها
- 🧩 معماری کاملاً ماژولار و قابل توسعه

> این پروژه هیچ قابلیت اسپم، دور زدن محدودیت‌های تلگرام یا سوءاستفاده از
> Bot API ندارد. تنها قابلیت خودکار هر ربات مدیریت‌شده، ری‌اکشن به پیام‌های
> دریافتی با یک ایموجی قابل تنظیم است (با استفاده از متد رسمی
> `setMessageReaction`).

## 📁 ساختار پروژه

```
manager/
├── main.py               # نقطه ورود برنامه
├── config.py              # بارگذاری و اعتبارسنجی تنظیمات از .env
├── database.py             # لایه دسترسی به دیتابیس SQLite (aiosqlite)
├── bot_manager.py           # مدیریت زنده اجرای نمونه‌های هر ربات
├── keyboards.py            # کیبوردهای اینلاین و CallbackData ها
├── requirements.txt
├── README.md
├── data.db                 # فایل دیتابیس SQLite (اسکیمای آماده)
├── handlers/
│   ├── __init__.py         # تجمیع تمام روترها
│   ├── start.py             # /start و منوی اصلی
│   ├── add_bot.py           # فلوی افزودن ربات (FSM)
│   ├── list_bots.py          # لیست و جزئیات ربات‌ها
│   ├── delete_bot.py          # حذف با تأیید
│   ├── reaction.py           # تغییر ایموجی ری‌اکشن (FSM)
│   └── settings.py           # فعال/غیرفعال کردن ربات
└── utils/
    ├── __init__.py
    ├── logger.py             # پیکربندی لاگر حرفه‌ای
    ├── validators.py           # اعتبارسنجی توکن، ایموجی و ورودی‌ها
    └── helpers.py             # ماسک توکن، فرمت تاریخ، فیلتر ادمین
```

## ⚙️ نصب وابستگی‌ها

نیازمند **Python 3.12** یا بالاتر است.

```bash
cd manager
python3 -m venv venv
source venv/bin/activate   # ویندوز: venv\Scripts\activate
pip install -r requirements.txt
```

## 🔐 ساخت فایل `.env`

فایل `.env.example` را کپی کرده و مقادیر آن را با اطلاعات واقعی خود جایگزین
کنید:

```bash
cp .env.example .env
```

سپس فایل `.env` را ویرایش کنید:

```env
BOT_TOKEN=توکن_ربات_مدیر_شما
ADMIN_IDS=111111111,222222222
DB_PATH=data.db
LOG_DIR=logs
DEFAULT_EMOJI=👍
```

| متغیر | توضیح |
|---|---|
| `BOT_TOKEN` | توکن ربات اصلی (مدیر)، از @BotFather دریافت کنید. |
| `ADMIN_IDS` | شناسه‌های عددی تلگرام کاربرانی که اجازه دسترسی به پنل را دارند (با کاما جدا شوند). |
| `DB_PATH` | مسیر فایل دیتابیس SQLite. |
| `LOG_DIR` | پوشه‌ای که فایل‌های لاگ در آن ذخیره می‌شوند. |
| `DEFAULT_EMOJI` | ایموجی ری‌اکشن پیش‌فرض برای ربات‌های تازه اضافه‌شده. |

شناسهٔ عددی تلگرام خود را می‌توانید با پیام دادن به ربات‌هایی مثل
`@userinfobot` بدست آورید.

## ▶️ اجرای پروژه

```bash
python3 main.py
```

پس از اجرا:

1. تمام ربات‌هایی که در دیتابیس فعال (`enabled = 1`) هستند به‌صورت خودکار
   راه‌اندازی می‌شوند.
2. ربات مدیر شروع به دریافت پیام می‌کند.
3. برای شروع کار با پنل، دستور `/start` را برای ربات مدیر ارسال کنید (فقط
   کاربرانی که در `ADMIN_IDS` تعریف شده‌اند اجازه دسترسی دارند).

## 🧭 استفاده از پنل

از منوی اصلی می‌توانید:

- **➕ افزودن ربات**: توکن ربات جدید را ارسال کنید تا پس از اعتبارسنجی از
  طریق `getMe`، به لیست ربات‌های مدیریت‌شده اضافه و بلافاصله اجرا شود.
- **📋 لیست ربات‌ها**: مشاهدهٔ همهٔ ربات‌ها و ورود به صفحهٔ جزئیات هر کدام.
- در صفحهٔ جزئیات هر ربات می‌توانید آن را **فعال/غیرفعال** کنید،
  **ایموجی ری‌اکشن** آن را تغییر دهید یا آن را **حذف** کنید (با تأیید).

## 🗄️ ساختار دیتابیس

**bots**

| فیلد | نوع | توضیح |
|---|---|---|
| id | INTEGER PK | شناسه داخلی ردیف |
| bot_id | INTEGER UNIQUE | شناسه عددی ربات در تلگرام |
| token | TEXT UNIQUE | توکن ربات |
| username | TEXT | یوزرنیم ربات |
| first_name | TEXT | نام نمایشی ربات |
| emoji | TEXT | ایموجی ری‌اکشن |
| enabled | INTEGER | ۱ فعال / ۰ غیرفعال |
| created_at | TEXT | تاریخ افزودن (ISO-8601) |

**settings** — جدول کلید/مقدار برای تنظیمات سراسری آینده.

**logs** — رخدادهای مهم (افزودن/حذف/تغییر وضعیت ربات‌ها) به همراه سطح، پیام،
شناسه ربات مرتبط و زمان ثبت.

## 📝 لاگ‌ها

لاگ‌ها در پوشهٔ تعیین‌شده توسط `LOG_DIR` (پیش‌فرض `logs/`) ذخیره می‌شوند:

- `manager.log` — تمام رخدادهای سطح INFO به بالا
- `errors.log` — فقط خطاها و Exception ها

علاوه بر فایل، رخدادهای مهم (افزودن/حذف/تغییر وضعیت ربات) در جدول `logs`
دیتابیس نیز ثبت می‌شوند تا بتوان تاریخچهٔ آن‌ها را از داخل خود پنل بازیابی
کرد.

## 🧱 توسعه در آینده

معماری پروژه کاملاً ماژولار است:

- برای افزودن یک قابلیت جدید در پنل، یک هندلر تازه در `handlers/` بسازید و
  روتر آن را در `handlers/__init__.py` ثبت کنید.
- تمام وابستگی‌های مشترک (`database`, `bot_manager`, `config`, `logger`)
  از طریق تزریق وابستگی (Dependency Injection) آیوگرم در اختیار هندلرها قرار
  می‌گیرند و نیازی به Singleton های سراسری پراکنده نیست.
- منطق اجرای زنده ربات‌ها در `bot_manager.py` از منطق پنل جدا شده تا بتوان
  رفتار هر ربات مدیریت‌شده (مثلاً افزودن قابلیت‌های جدید غیر از ری‌اکشن) را
  بدون دست‌زدن به کد پنل مدیریتی توسعه داد.

## ⚠️ محدودیت‌ها و قوانین استفاده

این پروژه هیچ ابزاری برای اسپم، دور زدن Rate Limit های تلگرام، جمع‌آوری
غیرمجاز اطلاعات یا هر نوع سوءاستفاده از Bot API ارائه نمی‌دهد و باید مطابق
[شرایط استفاده از Bot API تلگرام](https://core.telegram.org/bots/faq) به
کار گرفته شود.
